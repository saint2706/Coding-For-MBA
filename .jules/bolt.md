## 2025-02-15 - Cached DOM queries in high-frequency events
**Learning:** In the `ScrollProgress` component, the `document.querySelector` was being called during every single scroll event evaluation inside the `requestAnimationFrame`. Even with throttling, continuously querying the DOM within high-frequency event handlers like scrolling leads to unnecessary CPU overhead and potential layout thrashing.
**Action:** When evaluating scroll or other rapid events that depend on external DOM elements, cache the result of the query in a `useRef` and utilize the `element.isConnected` API to re-evaluate the target element ONLY when necessary (e.g. if the element is dynamically removed from the DOM). Remember to also reset the ref via a `useEffect` dependent on the selector string prop changes to ensure stale elements are safely discarded.
