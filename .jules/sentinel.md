## 2024-08-13 - [Command Injection via Missing CR Handling in Python Comment Stripping]
**Vulnerability:** The Python comment stripping logic in `stripPythonCommentsAndStrings` (`src/utils/codeSecurity.ts`) only looked for `\n` to mark the end of a comment, but ignored `\r` (carriage return). Python's runtime treats both `\n` and `\r` as valid newlines, allowing an attacker to hide malicious imports or functions (like `import js`) on the same line visually after a `\r`, which the comment stripper falsely treated as a comment and removed before security validation.
**Learning:** When sanitizing code (e.g., Python) before security validation, avoid relying solely on simple newline matching like `\n`. This can inadvertently strip malicious payloads disguised as comments inside strings or using alternative newlines, allowing command injection bypasses.
**Prevention:** Ensure the parser treats both carriage return (`\r`) and line feed (`\n`) characters as valid newlines by checking both or using a regex that handles both `\r` and `\n` when terminating comments.
