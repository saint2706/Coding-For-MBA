## 2024-11-20 - Python Comment Stripping Carriage Return Bypass
**Vulnerability:** The `stripPythonCommentsAndStrings` function in `src/utils/codeSecurity.ts` only checked for `\n` to signify the end of a comment. This allowed an attacker to use a carriage return `\r` to inject a malicious payload like `# comment\ros.system('evil')`. The validator would treat the payload as part of the comment and strip it, but the Python interpreter would execute it because it recognizes `\r` as a newline.
**Learning:** When sanitizing code (e.g., Python) before security validation, avoid relying solely on simple regular expressions or specific newline characters (like `\n`) for comment stripping. You must ensure the parser treats both carriage return (`\r`) and line feed (`\n`) characters as valid newlines to match the interpreter's lexical behavior.
**Prevention:** Always check for both `\n` and `\r` when determining the end of a line in a manual parsing loop, or preferably, use an AST or state-machine parser to accurately distinguish string literals from comments.
