## 2025-02-14 - Python Comment Stripping Bypass (Carriage Return)
**Vulnerability:** The `stripPythonCommentsAndStrings` function in `src/utils/codeSecurity.ts` only looked for `\n` to signify the end of a comment (`stripped.indexOf('\n', i)`). However, an attacker could use a carriage return `\r` (without a `\n`) to end a comment visually or lexically in some contexts, effectively hiding malicious code (like `import os`) in what the security scanner believed was still part of the comment, thereby bypassing the validation checks before passing the code to Pyodide.
**Learning:** Python (and other systems) may interpret `\r` as a newline/statement separator. When manually stripping comments for security validation, relying solely on `\n` is insufficient and creates an evasion vector where dangerous code following a `\r` is skipped by the validator but executed by the runtime.
**Prevention:** When parsing for the end of a line-based comment, always check for any newline character, including both `\n` (Line Feed) and `\r` (Carriage Return).
