# Internationalization (i18n) Guide

## Overview

The Coding for MBA curriculum supports internationalization to make learning accessible to non-English speakers.

## Current Status

- **Base Language**: English (en)
- **Available Translations**: Spanish (es) - Sample/Template
- **Framework**: JSON-based locale files with mkdocs-static-i18n plugin

## Quick Start

### For Learners

Switch language on the documentation site using the language selector in the top navigation.

### For Translators

1. **Extract strings**:
   ```bash
   python scripts/extract_i18n.py --output locales/en --format json
   ```

2. **Translate**:
   - Copy `locales/en/messages.json` to `locales/XX/messages.json` (where XX is your language code)
   - Translate the string values
   - Update metadata

3. **Test**:
   ```bash
   mkdocs serve
   ```

## Translation Workflow

### Step 1: Extract Translatable Strings

```bash
# Extract all translatable strings from lessons and docs
python scripts/extract_i18n.py --format json
```

This generates:
- `locales/en/messages.json` - English base
- `locales/es/messages.json` - Spanish template (partial)

### Step 2: Translate

Edit `locales/XX/messages.json`:

```json
{
  "metadata": {
    "language": "es",
    "version": "1.0",
    "last_updated": "2024-01-15",
    "translation_status": "complete"
  },
  "strings": {
    "Introduction to Python": "Introducción a Python",
    "Getting Started": "Empezando",
    "This lesson covers basic Python syntax": "Esta lección cubre la sintaxis básica de Python"
  }
}
```

### Step 3: Create Translated Pages

For key pages (index, roadmap), create translated versions:

**English**: `docs/index.md`
**Spanish**: `docs/index.es.md`

### Step 4: Configure MkDocs

Update `mkdocs.yml`:

```yaml
plugins:
  - i18n:
      default_language: en
      languages:
        en:
          name: English
          build: true
        es:
          name: Español
          build: true
      nav_translations:
        es:
          Home: Inicio
          Lessons: Lecciones
          Projects: Proyectos
```

### Step 5: Build and Test

```bash
# Serve with hot reload
mkdocs serve

# Build static site
mkdocs build

# Check language switcher appears in navigation
```

## Translation Guidelines

### What to Translate

✅ **Do translate**:
- Lesson titles and headings
- Explanatory text and instructions
- UI labels and navigation
- Business scenarios and examples

❌ **Don't translate**:
- Code snippets
- Variable names
- Function names
- File paths
- URLs

### Style Guide

1. **Consistency**: Use the same translation for repeated terms
2. **Technical Terms**: Keep technical terms in English if commonly used in programming (e.g., "Python", "DataFrame")
3. **Code Comments**: Translate comments in code examples
4. **Tone**: Maintain the educational, professional tone

### Example Translations

**English**: "This lesson teaches you how to use Python lists"
- **Spanish**: "Esta lección te enseña cómo usar listas en Python"
- **French**: "Cette leçon vous apprend à utiliser les listes Python"

## Translation Tools

### Recommended Tools

1. **Poedit**: GUI editor for PO/POT files
2. **Lokalize**: KDE translation tool
3. **VS Code**: With i18n extensions
4. **DeepL**: For initial drafts (requires human review)

### Automated Translation

⚠️ **Warning**: Never use fully automated translations without human review!

Safe workflow:
1. Use DeepL/Google Translate for initial draft
2. Have native speaker review and edit
3. Test in context (mkdocs build)
4. Iterate based on feedback

## Contributing Translations

### Process

1. **Fork repository**
2. **Create translation branch**: `feature/i18n-XX`
3. **Translate**:
   - Run extraction script
   - Translate strings in `locales/XX/messages.json`
   - Create `docs/index.XX.md`
4. **Test**:
   ```bash
   mkdocs serve
   # Check language switcher and translated pages
   ```
5. **Submit PR**:
   - Title: "Add [Language] translation"
   - Description: Translation status, tools used, review process

### Review Checklist

- [ ] All strings in `messages.json` translated
- [ ] Code snippets left in English
- [ ] Technical terms handled appropriately
- [ ] Home page (`index.XX.md`) created
- [ ] Navigation items translated in `mkdocs.yml`
- [ ] Tested with `mkdocs serve`
- [ ] Native speaker review completed

## Maintenance

### Updating Translations

When new lessons are added:

1. **Re-extract strings**:
   ```bash
   python scripts/extract_i18n.py
   ```

2. **Identify new strings**:
   Compare new `messages.json` with previous version

3. **Translate new strings**:
   Add translations to `locales/XX/messages.json`

4. **Test**: Ensure site builds without errors

## Technical Details

### Plugin Configuration

The `mkdocs-static-i18n` plugin:
- Builds separate site versions per language
- Automatically generates language switcher
- Supports per-page translations
- Falls back to default language for untranslated pages

### URL Structure

- English: `https://site.com/`
- Spanish: `https://site.com/es/`
- French: `https://site.com/fr/`

### Search

Each language version has its own search index for better results.

## FAQ

**Q: Can I translate just one lesson?**
A: Yes! Partial translations are welcome. Mark status as "partial" in metadata.

**Q: What if I find an error in the English version?**
A: Open an issue or PR to fix the English source first, then update translations.

**Q: How do I handle business terminology?**
A: Use terms common in business education for your region. Add glossary in PR description.

**Q: Should code output be translated?**
A: No, keep code output in English to match what learners see when running code.
